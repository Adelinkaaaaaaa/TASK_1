## Шаг 3. Спрячь пароли — `.gitignore`

**`.gitignore`** — это обычный текстовый файл со списком того, что Git должен **игнорировать**: не показывать в `git status` и не добавлять в коммиты. В каждой строке — имя файла или папки.

Создай файл `.gitignore` в корне репозитория и запиши в него одну строку:

```
passwords.txt
```

Сделать это можно в Блокноте или одной командой через `echo` и `>` — как ты создавал `answer.txt` в Q2. Попробуй составить команду сам.

> 💡 Имя файла начинается с точки — это не опечатка. Файлы с точкой в начале считаются **скрытыми**: обычный `ls` их не показывает. Чтобы убедиться, что файл создан, используй `ls -a`.

Проверь `git status` ещё раз:

```
On branch q3
Your branch is up to date with 'origin/q3'.

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore
        commands.txt
```

`passwords.txt` **исчез** из списка — Git его больше не замечает. Сам файл никуда не делся: проверь через `ls`.

Зато появился `.gitignore` — его как раз нужно закоммитить, чтобы правило работало у всех, кто скачает репозиторий.

Добавь `.gitignore` и `commands.txt`, сделай коммит и отправь его в свою копию (`git push`). Теперь можно смело делать даже `git add .` — пароли туда не попадут.

## Шаг 4. Создай свой репозиторий на GitHub

До сих пор ты работал в **копии** репозитория организаторов (форке). Настоящие проекты обычно начинаются с собственного, пустого репозитория. Создадим его.

1. Открой https://github.com/new
2. **Repository name** — `TASK1_3`.
3. Видимость — **Public**.
4. ⚠️ **Ничего не добавляй**: не ставь галочку **Add a README file**, в полях **.gitignore** и **license** оставь **None**. Репозиторий должен быть совсем пустым.
5. Нажми **Create repository**.

GitHub откроет страницу с инструкциями. Нам с неё нужен только **адрес** в поле **Quick setup** — убедись, что выбрано **HTTPS**, и скопируй его. Он выглядит так: `https://github.com/ТВОЙ_НИК/TASK1_3.git`.

> ⚠️ **Не копируй команды с этой страницы целиком!** Там есть `git branch -M main` — она переименует твою ветку `q3` в `main`. Нам это не нужно.

## Шаг 5. Подключи новый репозиторий — `git remote`

### Что такое remote

**Remote** (от англ. «удалённый») — это адрес репозитория на сервере, с которым связан твой локальный репозиторий. У каждого remote есть короткое имя, чтобы не писать длинный адрес каждый раз.

Посмотри, какие remote есть сейчас:

```bash
git remote -v
```

```
origin  https://github.com/ТВОЙ_НИК/TASK_1.git (fetch)
origin  https://github.com/ТВОЙ_НИК/TASK_1.git (push)
```

Сейчас он один — `origin`, твоя копия заданий. Именно туда уходил каждый твой `git push`. (`fetch` и `push` — адреса для скачивания и отправки, обычно они совпадают.)

### Переименуй старый remote

Имя `origin` по традиции дают **главному** репозиторию проекта. Главным теперь станет твой новый репозиторий, поэтому старый переименуем в `fork`. Команда для переименования устроена так:

```
git remote rename старое_имя новое_имя
```

Составь команду, которая переименует `origin` в `fork`, и проверь результат командой `git remote -v` — вместо `origin` должно стоять `fork`.

### Добавь новый remote

Команда для добавления устроена так:

```
git remote add имя адрес
```

Добавь свой новый репозиторий под именем `origin`. Адрес ты скопировал в шаге 4 — вставь его через **Shift + Insert**. Составь команду сам.

Проверь, что получилось:

```bash
git remote -v
```

```
fork    https://github.com/ТВОЙ_НИК/TASK_1.git (fetch)
fork    https://github.com/ТВОЙ_НИК/TASK_1.git (push)
origin  https://github.com/ТВОЙ_НИК/TASK1_3.git (fetch)
origin  https://github.com/ТВОЙ_НИК/TASK1_3.git (push)
```

Теперь у твоего репозитория **два** remote: старая копия заданий и новый собственный репозиторий.

## Шаг 6. Отправь работу в новый репозиторий

Сначала допиши в журнал все команды, которые ты вводил, сохрани его и сделай коммит (`add` + `commit`, как обычно).

Обычный `git push` сейчас не подойдёт: ветка `q3` всё ещё связана со старым remote — с `fork`. Нужно явно сказать Git, **куда** и **какую ветку** отправлять:

```
git push -u куда какую_ветку
```

- `куда` — имя remote, в который нужно отправить;
- `какую_ветку` — имя ветки, которую отправляешь;
- `-u` — запомнить этот выбор. После этого в этой ветке можно снова писать просто `git push`, и Git будет отправлять туда же.

Составь команду, которая отправит ветку `q3` в твой новый репозиторий(`origin`). Если всё верно, Git ответит:

```
...
To https://github.com/ТВОЙ_НИК/TASK1_3.git
 * [new branch]      q3 -> q3
branch 'q3' set up to track 'origin/q3'.
```

`[new branch]` — в новом репозитории появилась ветка `q3`. Проверь состояние репозитория: должно быть `up to date with 'origin/q3'` — теперь ветка связана с новым репозиторием.

Открой `https://github.com/ТВОЙ_НИК/TASK1_3` в браузере. Там должны быть `README.md`, `create_passwords.sh`, `.gitattributes`, `.gitignore` и `commands.txt` — и **не должно быть** `passwords.txt`. 🎉

## Если что-то пошло не так

<details>
<summary><code>passwords.txt</code> всё ещё виден в <code>git status</code></summary>

- Проверь, что файл называется именно `.gitignore` — с точкой в начале и без `.txt` в конце (`ls -a`).
- Проверь, что он лежит в корне репозитория, рядом с `README.md`, а не в другой папке.
- Проверь содержимое (`cat .gitignore`): имя файла должно быть написано точно, без лишних пробелов и кавычек.
</details>

<details>
<summary>Я уже сделал <code>git add</code> с паролями, но ещё не закоммитил</summary>

Убери файл из «коробки» — сам файл при этом останется в папке:

```bash
git restore --staged passwords.txt
```
</details>

<details>
<summary>Я уже закоммитил <code>passwords.txt</code></summary>

Скажи Git перестать следить за файлом (файл останется в папке) и сделай коммит:

```bash
git rm --cached passwords.txt
git commit -m "Убрал пароли из репозитория"
```

После этого добавь `passwords.txt` в `.gitignore`, если ещё не добавил.

⚠️ Пароли всё равно останутся в **истории** — в старом коммите. В реальной жизни после такого все пароли из файла срочно меняют. Именно поэтому `.gitignore` создают **до** первого коммита.
</details>

<details>
<summary><code>error: remote origin already exists</code></summary>

Ты пытаешься добавить `origin`, но старый ещё не переименован. Сначала переименуй старый `origin` в `fork`, потом снова добавь новый.
</details>

<details>
<summary>Ошибся в адресе при <code>git remote add</code></summary>

Исправь адрес — переделывать всё не нужно:

```bash
git remote set-url origin https://github.com/ТВОЙ_НИК/TASK1_3.git
```
</details>

<details>
<summary><code>git push</code>: <code>Repository not found</code></summary>

Проверь через `git remote -v`, что в адресе `origin` правильный ник и имя `TASK1_3` (с цифрой, подчёркиванием и большими буквами — точно как на GitHub). Исправить адрес можно через `git remote set-url` (см. выше).
</details>

<details>
<summary><code>git push</code>: <code>! [rejected] ... (fetch first)</code></summary>

В новом репозитории уже что-то есть — скорее всего, при создании была галочка **Add a README file**. Проще всего удалить репозиторий `TASK1_3` на GitHub (**Settings** → в самом низу **Delete this repository**), создать его заново **пустым** и снова отправить ветку `q3`.
</details>

<details>
<summary>Ветка <code>q3</code> превратилась в <code>main</code></summary>

Ты скопировал со страницы GitHub команду `git branch -M main`. Верни имя обратно:

```bash
git branch -m main q3
```
</details>
