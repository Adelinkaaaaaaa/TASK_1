# Q2. Поиск по архиву

Компания **ООО «Рога и Копыта»** хранила документы как попало: накладные, счета, договоры, отчёты и служебные записки разложены по годам и отделам, а в одном из отчётов больше тысячи строк. Где-то в этом архиве спрятано **кодовое слово**.

Открывать и читать глазами каждый файл — долго. Программисты в таких случаях используют команду **`grep`**: она за долю секунды просматривает все файлы и находит нужные строки. Сегодня ты научишься ею пользоваться.

> 🔑 **У каждого участника своё кодовое слово** — оно зависит от твоей почты в настройках Git.

---

## Шаг 1. Переключись на ветку `q2`

Проверь, что задание Q1 сдано: `git status` должен показывать `up to date with 'origin/q1'` и `working tree clean`.

Переключись на ветку `q2` — команду ты уже знаешь из Q1. Git должен ответить:

```
branch 'q2' set up to track 'origin/q2'.
Switched to a new branch 'q2'
```

Посмотри, что теперь лежит в папке. Должно быть так:

```
README.md  restore_archive.sh
```

> 🤔 **А где мой `about.md`?** Он никуда не делся. Он находится в ветке `q1`, а сейчас ты в ветке `q2`. Если переключиться обратно (`git switch q1`), файл появится снова. В этом и смысл веток: в каждой — своя версия файлов.

## Шаг 2. Восстанови архив

В ветке лежит скрипт `restore_archive.sh` — маленькая программа, которая создаст архив компании. Запусти её:

```bash
bash restore_archive.sh
```

```
Восстанавливаю архив ООО «Рога и Копыта»...

Готово! Восстановлено документов: 15
Архив лежит в папке archive.
```

Проверь, что папка появилась и Git её увидел (`git status`).

## Шаг 3. Знакомство с `grep`

### 📝 Журнал команд — обязательно!

Начиная с этого шага, **записывай каждую команду, которую ты вводишь**, в файл `commands.txt`. Сдашь его вместе с ответом — по нему мы увидим, как ты решал задание.

Создай пустой файл `commands.txt` в корне репозитория (рядом с `README.md`) и открой его в Блокноте. Выполнил команду — скопируй её в Блокнот и сохрани (**Ctrl + S**).

> 💡 Когда открываешь Блокнот из терминала, допиши в конце команды `&` — например, `notepad имя_файла &`. `&` значит «запусти и не жди»: Блокнот откроется, а терминал останется свободным. Без `&` терминал будет ждать, пока ты не закроешь Блокнот, — а нам нужно, чтобы оба окна работали одновременно.

Пиши в журнал **всё, включая неудачные попытки**: команды с ошибками, поиски, которые ничего не нашли. Это не минус, а плюс — так видно, как ты думал. Можешь подписывать, к какому шагу относятся команды.

> 💡 Забыл, что вводил? Команда `history` покажет список всех твоих последних команд.

### Осмотрись

Перейди в папку `archive` и осмотрись.

Архив устроен так: **год → отдел → документы**. Отделы: `sklad` (склад), `buhgalteriya` (бухгалтерия), `prodazhi` (продажи), `kadry` (отдел кадров).

### Поиск в одном файле

Как устроена команда:

```
grep "что ищем" где_ищем
```

Найди строку со словом `Сумма` (с большой буквы) в файле `2022/buhgalteriya/schet_0001.txt`. Составь команду по шаблону выше. Должно написать вот так:

```
Сумма к оплате: 48 500 руб., в т. ч. НДС 20%
```

grep показал только ту строку файла, где есть слово `Сумма`.

### Поиск во всех файлах сразу

Добавь ключ `-r`, а вместо имени файла поставь точку `.` — «текущая папка»:

```bash
grep -r "Earl Grey" .
```

Экран заполнится десятками строк — grep просмотрел **все** файлы во всех папках. Каждая строка ответа устроена так:

```
./2022/sklad/nakladnaya_0002.txt:2. Чай Earl Grey — 20 шт. × 300 руб.
└──────── в каком файле ───────┘ └──────── найденная строка ───────┘
```

До двоеточия — путь к файлу, после — сама строка.

### Большие и маленькие буквы

Попробуй найти во всех файлах `earl grey` — маленькими буквами. Ничего не нашлось? Это потому, что grep **различает** большие и маленькие буквы, а в документах написано `Earl Grey`.

Ключ `-i` (от *ignore case* — «не обращать внимания на регистр») это исправляет. Добавь его к своей команде — найди `earl grey` маленькими буквами так, чтобы grep нашёл все строки с `Earl Grey`.

### Только имена файлов

Иногда сами строки не нужны — достаточно узнать, **в каких файлах** есть слово. Для этого есть ключ `-l` (от *list* — «список»). Составь команду, которая будет искать "Earl Grey" во всех файлах. Вывод должен быть таким (строки могут идти в другом порядке — это нормально):

```
./2022/sklad/nakladnaya_0002.txt
./2023/sklad/nakladnaya_0005.txt
./2024/sklad/otchet_0010.txt
./2025/buhgalteriya/otchet_0015.txt
./2025/sklad/pismo_0014.txt
```

### Шпаргалка

| Команда | Что делает |
|---|---|
| `grep "слово" файл` | Ищет строки со словом в одном файле |
| `grep -r "слово" .` | Ищет во всех файлах текущей папки и всех вложенных папок |
| `grep -ri "слово" .` | То же, но без учёта регистра: найдёт и `слово`, и `СЛОВО`, и `сЛоВо` |
| `grep -rl "слово" .` | Показывает только имена файлов, в которых есть слово |

Ключи можно объединять: `-ri`, `-rl`, `-ril` — как удобно.

> 💡 Если вывод слишком длинный — нажми **Ctrl + C**, чтобы остановить его, и `clear`, чтобы очистить экран.

## Шаг 4. Найди кодовое слово

Теперь самостоятельно. Тебя ждут **две подсказки**: первая говорит, где искать вторую, а вторая — где лежит кодовое слово. В конце ты найдёшь строку вида:

```
CODE: СЛОВО
```

**Первая подсказка спрятана в строке со словом `HINT-1`.** Дальше — читай подсказки внимательно. Все нужные инструменты есть в шпаргалке выше.

> ⚠️ В архиве есть и другие строки `CODE:` с разными словами — это ловушки. Верная строка только одна, и найти её можно только по подсказкам.

Полезное:

- Не забывай записывать команды в `commands.txt`.
- Ищи из папки `archive` — проверь через `pwd`, где ты.
- Путь к файлу из ответа grep можно выделить мышкой (он скопируется сам) и вставить после `cat ` через **Shift + Insert**.
- Застрял на какой-то подсказке — перечитай её ещё раз, каждое слово там не случайно.

## Шаг 5. Сдай ответ

Нашёл слово? Запомни его (или скопируй) и **вернись из архива на уровень выше — в корень репозитория**. Проверь, где ты: путь должен заканчиваться на `/TASK_1` — там же, где лежит `README.md`.

Создадим файл с ответом. На этот раз без Блокнота — одной командой:

```bash
echo "ТВОЁ_СЛОВО" > answer.txt
```

Вместо `ТВОЁ_СЛОВО` напиши найденное слово — например, `echo "SLOVO" > answer.txt`.

- `echo` — печатает текст;
- `>` — направляет этот текст не на экран, а в файл `answer.txt`. Если файла нет, он создастся, а если есть — перезапишется.

Проверь, что в журнале `commands.txt` есть все команды, которые ты вводил, и что он сохранён. Добавь в коммит `answer.txt`, `commands.txt` и папку `archive`, закоммить и не забудь запушить!

Открой свою копию на GitHub, выбери ветку `q2` и убедись, что там появились `answer.txt`, `commands.txt` и папка `archive`.

## Если что-то пошло не так

<details>
<summary><code>bash: restore_archive.sh: No such file or directory</code></summary>

Ты не в той папке или не в той ветке. Перейди в папку репозитория (`~/projects/TASK_1`) и проверь состояние: должно быть `On branch q2`. Если нет — переключись на ветку `q2`.
</details>

<details>
<summary>Скрипт пишет «Git не знает твою почту»</summary>

Ты пропустил настройку из Q0. Выполни (со своей почтой с GitHub):

```bash
git config --global user.email "твоя@почта.ru"
```

И запусти скрипт ещё раз.
</details>

<details>
<summary>Случайно удалил архив или запустил скрипт ещё раз</summary>

Ничего страшного. Скрипт можно запускать сколько угодно раз — он пересоздаст архив точно таким же, и твоё кодовое слово не изменится.
</details>

<details>
<summary>grep ничего не находит</summary>

- Проверь, что ты в папке `archive`: `pwd` должен заканчиваться на `/archive`.
- Проверь, не забыл ли ты `-r` и точку в конце.
- Помни: без `-i` grep различает большие и маленькие буквы.
</details>

<details>
<summary><code>answer.txt</code> оказался в папке <code>archive</code></summary>

Ты создал файл, не выйдя из архива. В `git status` он виден как `archive/answer.txt`. Перейди в корень репозитория и переложи файл командой `mv` (от *move*, «переместить»):

```
mv откуда куда
```

Например, `mv archive/answer.txt .` — переложит файл из `archive` в текущую папку (`.`). После этого сделай коммит и отправь его на GitHub, как обычно.
</details>

<details>
<summary>Закрыл Блокнот с журналом</summary>

Открой его снова — из корня репозитория (`notepad commands.txt &`) или из папки архива (`notepad ../commands.txt &`). Главное — не создавай второй `commands.txt` внутри `archive`.
</details>

<details>
<summary>Ошибся в слове и уже сделал push</summary>

Это нормально. Перезапиши `answer.txt` верным словом (так же, как создавал его в шаге 5 — `>` заменит старое содержимое), сделай новый коммит и снова отправь его на GitHub.
</details>
